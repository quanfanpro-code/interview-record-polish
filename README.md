# interview-record-polish

把访谈录音的转写稿，整理成一份能直接进尽调底稿的访谈记录。

一份好的访谈记录不是把录音抄下来。它要保留问答的骨架，但要按业务逻辑重新组织：一个问题提炼成一句专业问句，一个回答整合成一段完整表述，一个业务维度下只留 2 到 4 组问答。

## 它解决什么问题

录音转写稿直接交上去有三个毛病：

1. **一问一答太碎**。原始对话里，同一个问题常被拆成三四轮追问，读的人得自己把业务逻辑拼起来。
2. **口语腔重**。大量"然后""就是说""差不多""应该是这样"，不能出现在底稿里。
3. **AI 味重**。如果整理稿是用 AI 生成的，往往带书面腔——提示性冒号、破折号、括号注解、整齐排比、汇报腔词汇。

本技能把这三件事一起处理掉，同时守住一条底线：**事实一个字都不动**。

## 安装

把整个 `interview-record-polish` 文件夹放进你的技能目录即可：

- 用户级（对所有项目生效）：`~/.workbuddy/skills/`
- 项目级（只在当前项目生效）：`{项目}/.workbuddy/skills/`

## 使用

直接对它说：

> 把这份访谈录音整理稿整理一下，精简、去 AI 味

技能会被自动触发。也可以显式点名：

> 用 interview-record-polish 整理这份访谈记录

## 产出长什么样

**整理前**（原始转写，三问三答，问的是同一件事）：

```
提问方：你们有没有按项目（材料、人工、每个项目多少）的台账？
回答方：那个我去找一下，应该是有的，申报的时候应该也需要这个东西。
提问方：研发费用中是工占大头还是什么占大头？审计报告里没有写明细。
回答方：应该是金刚石项目那个比较多，具体要按项目看一下。材料、人工、折旧这些的明细，应该有台账。
```

**整理后**（一问一答，问题提炼、答复整合）：

```
问：研发费用的构成和台账情况如何？
答：费用构成以金刚石项目比较多，具体还要按项目看。材料、人工、折旧的明细应该有台账，公司表示需要回去查找，申报时也需要这套东西。
```

## 整理原则

| 项目 | 规则 |
|---|---|
| 问答标记 | 只用 `问：` `答：`，不用"提问方／回答方" |
| 问题 | 一轮碎问合并成一句提炼过的专业问句，可含两个小问 |
| 回答 | 几轮零碎答复合成一段完整书面表述 |
| 议题 | 按业务维度划分，每个议题下 2 到 4 组问答 |
| 头部字段 | 访谈记录 / 被访谈单位 / 访谈内容 / 被访谈人 / 访谈人 / 访谈地点 / 访谈时间 |
| 事实 | 数字、人名、公司名、待办一条不丢 |
| 矛盾 | 原稿前后对不上的地方照实保留，不替它圆 |

## 三条容易踩的坑

1. **"不要一问一答的腔调"不等于取消问答体**。用户说这句话时，他要的是提炼和整合，不是把问答改成纯叙述。先要样板，或找一份同类底稿比对。
2. **括号注解要分类处理**。纯冗余的删掉（`工和费（加工费用）`），术语别名对应的保留（`订单（计划号）`）。
3. **矛盾数据不是错误**。走访听到"几千万"、公司答复"两百多万"，两个数都要留着，这本身就是尽调发现。
